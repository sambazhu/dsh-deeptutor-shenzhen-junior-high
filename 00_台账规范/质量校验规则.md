# 质量校验与并发规则

> 2026-10-16 第一次端到端测试后新增。目标：避免模型把“看起来对”的推导写进台账，也避免 Web 与微信两个会话同时改同一份资料。

## 一、事实、推理、待确认三层分离

| 层级 | 内容 | 记录要求 |
|---|---|---|
| 卷面事实 | 孩子写了什么、老师红笔怎么批、家长原话 | 以原件为准；看不清就标 `❓待确认` |
| 模型推理 | 解题过程、判断对错、错因分类 | 必须经过独立验证后才能写成结论 |
| 待确认 | 信息不足、批改口径不明、OCR 不确定 | 只写“待复核”，不得硬填“正确答案” |

## 二、数学/理科题复核流程

1. 先用与卷面不同的方法独立推导一遍；
2. 组合、展开图、计数、动点等易错题型，尽量用程序枚举或第二种方法验证；
3. 两种方法结果一致，才可以在错题本里写“正确/错误”；
4. 仍不确定时，记录“孩子原答案 + 待老师/家长确认”，不要写模型猜的答案；
5. 老师已判错但模型觉得对：保留老师批改事实，另写“模型复核结果”，并标注需要确认判分口径。

## 三、图片/PDF 处理

- 图片版 PDF：优先用 `pdftoppm` 按页渲染，再交给模型视觉能力或 `read_image`（如工具可用）；
- 不要在会话中执行 `swiftc -O` 之类可能长时间阻塞的编译；本地 OCR 不可用就换视觉通道；
- OCR 结果与手写内容不确定时，以原图为准，并保留“OCR 不确定处”。

## 四、并发处理锁

- Web 会话和微信 IM 会话共用同一个工作区，同一份资料**只允许一个会话写入台账**；
- 处理前在 `00_收件箱/待处理/` 创建 `<原文件名>.processing`，写入会话标识和处理开始时间；
- 处理完成后删除 `.processing`，把原件移入 `00_收件箱/已处理/YYYY-MM-DD/`；
- 另一个会话看到有效 `.processing` 锁时只读、不写，避免重复登记或互相覆盖；
- Excel 等共享文件写入前，先重新加载一次最新版本，避免覆盖别的会话已写入的行。

## 五、文字先到、附件后到

- 家长说“这个/那张试卷”但附件还没到：先建轻量 `_待附件` 占位，不要立刻写正式错题条目；
- 建议等待 2—3 分钟或先问一句“附件是否已发”；
- 附件到达后合并成一个记录，并更新占位文件状态；
- 推荐发送方式：文件 + 说明放同一条消息；如果分开发，先发文件，再发文字说明。
