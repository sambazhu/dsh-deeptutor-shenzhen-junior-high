# 提醒工具（09_提醒工具）

给秋宇的定时微信提醒。链路：**时间表文件 → 守护进程 → DSH-IM 主动投递接口 → 微信**（同时弹 macOS 桌面通知作后备）。

> 建这套东西是因为：助手自己不能定时唤醒、也不能主动发消息；但 IM 插件提供主动投递接口，配合一个本机常驻脚本就能做到“到点自动发微信”。

## 文件说明

| 文件 | 作用 |
|---|---|
| `reminders.tsv` | **时间表**（要改的就是它）：每行 `YYYY-MM-DD HH:MM<TAB>要发的文字` |
| `run_reminders.sh` | 守护进程：每 20 秒检查一次时间表，到点调用发送脚本 |
| `send_reminder.sh` | 发送器：POST 到 `http://127.0.0.1:19387/api/dsh-im/delivery/messages`，并弹桌面通知 |
| `stop_reminders.sh` | 停止守护进程 |
| `digest.sh` | **每日摘要生成器**：读《学习计划_期中复习.md》取当天复习任务 + 读 reminders.tsv 取近三天提醒，拼成微信摘要 |
| `今日补充_YYYY-MM-DD.txt` | 可选：当天临时补充的内容（会显示在摘要最前面） |
| `heartbeat.txt` | 心跳日志（每 5 分钟一条 `alive`；看这里判断守护进程是否还活着） |
| `fired.log` | 已触发的提醒（防止重复发送） |
| `sent.log` | 每次实际发送的接口返回（`{"sent":true}` 才算成功） |
| `daemon.pid` / `daemon.log` | 进程号与标准输出 |

## 常用操作

```bash
cd "/Users/sambazhu/dshworkplace/朱秋宇初一学习台账/09_提醒工具"

# 启动（后台常驻，关掉终端也不影响）
nohup ./run_reminders.sh > daemon.log 2>&1 &

# 查看是否还在跑
cat daemon.pid; tail -3 heartbeat.txt; pgrep -f run_reminders.sh

# 停止
./stop_reminders.sh

# 手动发一条（立即发送，测试用）
./send_reminder.sh "测试：这条是手动发的"
```

**增删提醒**：只改 `reminders.tsv`，不用重启守护进程（它每轮都会重新读）。注意时间列与文字之间必须是 **Tab**，不是空格。

## 每天 18:00 微信摘要

- `reminders.tsv` 里有一行固定任务：`@daily 18:00<TAB>@digest`
- 到 18:00，守护进程会调用 `digest.sh` 生成摘要再发微信，内容包括：
  1. 今日复习任务（从 `00_每日作业与待办/2026-11/学习计划_期中复习.md` 按日期取那一行）
  2. 今天剩余 + 明天 + 后天的提醒（前 70 字）
  3. 若存在 `今日补充_YYYY-MM-DD.txt`，会把它放在最前面
- 想改摘要内容：改 `digest.sh`；想临时加一句：写 `今日补充_$(date +%F).txt`
- 想关掉每日摘要：删掉或注释 `@daily 18:00` 那行即可（不用重启）

## 已知限制（务必知道）

1. **DSH 桌面应用必须开着、电脑不能睡眠**：投递接口跑在 DSH 的 WebServer 上，App 一退出就发不出去。晚上记得让电脑别睡眠（或至少 20:30–21:30 保持唤醒）。
2. **微信侧仍受平台规则约束**：插件文档写明“微信是否接受发送仍受 iLink 服务端规则约束”；失败会记在 `sent.log`，不会静默。
3. **macOS 桌面通知是后备**：即使微信没发出去，电脑也会弹一条提醒。
4. **launchd 定时（写 `~/Library/LaunchAgents`）在本机被沙箱禁止**，所以用常驻进程方案；如果哪天想改成开机自启，需要在系统层面手动授权。
5. 守护进程本身不会开机自启，**电脑重启后需要重新执行一次启动命令**（或让助手在下次对话里帮你拉起）。
